**源码执行链**（固定 commit `1cdff93f03711b4dc21c1424d8bc530c6afed888`）：Zapier monolith 生成 event → AWS Lambda → `createLambdaHandler` 建立受控上下文 → 加载 app definition + Schema prepare/validation → 生成 bundle（environment/authData/inputData）→ `createApp` 运行开发者 `perform(z, bundle)` → `z.request` 统一插入 auth / sanitization / logging / stale-auth refresh / throttle / status handling → 回传后端。

**两套验签机制不能混（实现级陷阱）**
- **Action Run Callback**：`Zapier-Callback-Signature` = JWT，用 Zapier JWKS 公钥验 RS256；含 iat/exp，约 5 分钟有效；5xx/网络错误指数退避最多 3 次，**4xx 不重试**；按 run_id 幂等；callback 失败仍可 GET 结果兜底
- **Connection Webhook**：Standard Webhooks 规范，**必须用 raw body** 验签，签名内容由 `webhook-id` + `webhook-timestamp` + raw body 构成；HMAC-SHA256 常量时间比较；`whsec_*` secret 仅创建时返回，丢失需删掉重建
- → **Matbox Adapter 必须分开实现，写成一套即生产事故。**

**action id 是 ephemeral，developer key 才稳定**：官方要求每次 `POST /v2/action-runs/` 前重新 Get Actions 拿新 id；旧 id 不能持久化成业务契约。输入字段需按 Action schema 加载 `/inputs`，SELECT 字段可能继续调 `/choices`。

**Issue #1329**：19.1.0 下 `cleanInputData=false` 仍可能让 null 从 `bundle.inputData` 消失（`inputDataRaw` 仍在）。对订单/库存/设计参数，null=清空 vs absent=保持原值不是小 bug。

**INC-547 安全事件**：官方文档有专页 `docs.zapier.com/integrations/build-cli/inc-547.md`，记录 Connector SDK 的 **NPM 供应链安全事件**。→ 自建 Connector SDK 的供应链风险有现成先例。

**Partner Sandbox（ZPS）**：给开发者免费开发额度 + 近生产测试环境。

**版本硬规则**（Platform News 2026）：版本号**不能跳号**；迁移**必须在同一 major 内**；`migrate` 只用于非破坏性变更，`deprecate` 用于破坏性/将停支持版本。版本生命周期：Private → Promoted → Available/Legacy → Deprecating → Deprecated（Deprecated 后旧 Zap 会被暂停）。

**Trigger 三套模型**：Polling（1–15min，需唯一 ID 去重）/ REST Hook（每 Zap 独立订阅，需 polling fallback 抓样本）/ **Trigger Inbox**（create/ensure/get/list/pause/resume/delete + message lease/ack/release + SSE；`PUT ensure` 用 key 幂等，同 key 不同配置返 409；release **不退还** lease attempt，达阈值可能 quarantine）。

# 2｜Microsoft Copilot Studio / Power Platform

## 2.1 ✅ 官方逐字命中

**Advanced Connector Policies（learn.microsoft.com/power-platform/admin/advanced-connector-policies）**
- default-deny：`a strict allowlist that blocks all connectors by default`；`New connectors added to the platform are automatically blocked.`
- **覆盖范围限制**：`Advanced connector policies currently apply to certified connectors only. Custom connectors and HTTP connectors aren't yet supported.` → 自定义与 HTTP 连接器**今天仍归 classic Data Policy 管**
- **MCP 粒度**：`granular control over individual MCP tools (endpoints and actions) within an MCP server isn't available. Blocking the entire MCP server is supported.`
- **Managed Environment 前提**：非托管环境上 nonblockable connectors **仍然封不掉**；只有托管环境能封任意 connector/action
- **GA 定义**：design-time enforcement 按 Power Automate → Copilot Studio → Power Apps 顺序 rollout，且 `Each maker portal's release of design-time enforcement for ACP marks the general availability of ACP for that workload.` → **在此之前 ACP 对该 workload 只是运行时拦截**
- **Virtual connectors 永不支持**；Copilot Studio 的 virtual connectors 今天仍须用 classic data policy
- **策略移除不级联**：环境保留最后一次 ACP 配置

**Job 状态映射（关键警告）**
| Canonical | UiPath | 开发含义 |
|---|---|---|
| QUEUED | Pending | **等待 Robot/Connection/资源，不是失败** |
| RUNNING | Running | 已开始执行 |
| STOPPING / TERMINATING | Stopping / Terminating | 中间态 |
| WAITING_HUMAN_OR_EVENT | Suspended | 长流程等待 |

| CANCELLED | Stopped | 被 Kill/取消 |

> **`Faulted` 不等于可安全重试**；`Pending` 是等资源不是失败。Adapter 必须把两者分开，否则就是盲重试。

**Queue / Transaction 模型**：Queue 是持久 Work Item 容器；Reference 可在 Queue 级**强制唯一**（重复添加会失败）；状态 New / In Progress / Successful / Failed / Abandoned；**Business Exception 与 Application Exception 分类**，Application Error 可按队列策略自动重试；Queue Item 可挂 JSON Schema；支持数据库加密与保留策略；Queue Trigger 按 pending/running jobs 与 items 数量计算新 Job 数，有 30 分钟 recheck。
> 收口句：**AI 员工的生产执行必须先写 Work Item 再消费，不能把 LLM 的一次 Tool Call 当成任务状态。**

**四类 Trigger**：Time（Cron/计划）/ Queue（积压或新增）/ Event（Integration Service 事件，**Connection 删除会级联删 Trigger**）/ API（HTTP 启动 Process，有同步/异步 call mode）。**Orchestrator 在 Trigger 连续失败时会自动禁用**——业务会静默停止，必须有 Trigger health alert。

**Robot / Machine / Session**：Service Mode（Local System 启动，可自动开 Windows session）是正式 Unattended 首选；User Mode 需用户登录、无自动 Session 管理，不适合后台关键任务；**无凭据 Robot 只能跑 Background Session 0，不能跑需要 UI 的前台流程**；Runtime slot 是容量/成本单位。→ 用户正在使用的桌面不能被默认拿来跑 Unattended。

**Asset 跨 Folder 撞车（真陷阱）**：不同 Folder 里使用同名 Orchestrator Asset 和同一外部名时，**可能指向同一个外部 Credential Store 对象**，在一个 Folder 修改会影响其他链接。→ Vault Ref 必须全局唯一 + Tenant-bound，禁止靠"名字相同"推断 Secret identity。

**Credential 子系统**：Credential Stores + **Orchestrator Credentials Proxy**（含独立调试页），支持 CyberArk、Azure Key Vault、HashiCorp Vault、AWS Secrets Manager、Google Secret Manager。Asset 有 "Automations only" 与 "Automations and API" 两种访问范围。

**MCP Server 作为 Folder 资源受 RBAC 管**：支持 UiPath / coded / command / remote 四类 Server；认证含 OAuth / PAT / External App / CLI interactive / ground-to-cloud；可用 `%ASSETS/AssetName%` 往 MCP header/env 注入密钥；Orchestrator 内可测试；有 MCP compliance guidelines。→ **风险：远程 MCP endpoint 可能把注入的密钥带走，必须 trusted endpoint allowlist。**

**源码级发现**（`UiPath/skills` 仓库）：Integration Service 运行时叫 **Udon**，夹在 Studio 与 Vendor API 之间统一处理认证、分页、参数映射、错误；API Workflow 会把 Connector activity 抽成 canonical **`bindings_v2.json`**，多个 Activity 共享 Connection UUID 时去重为一个 binding；Planner 模板要求在设计文档里明确 Integration Service / Custom Connector / Direct HTTP 三种访问路径；Coded Agent quickstart 明确 Connector activity metadata 需要真实认证后的 `resources describe`——**供应商 Action schema 不能靠 LLM 猜**。

**Connector Builder 边界**：只支持 **REST + JSON**，官方 skills 文档把 **GraphQL / SOAP / XML / 多 base-url 明确列为 out of scope**。

**其他运行约束**：**Robot 日志超过 50KB 会被直接忽略**（证据会静默丢失）；**Enterprise 版 Connector 上线比 Community 晚 1 小时到 14 天甚至更久**；**Integration Service 旧 outbound IP 从 2026-09-16 起逐步退役**（会打断已部署集成的真实网络变更）；Integration Service Connector 带 New/Preview/Updated 生命周期标签，官方明确 **Preview Connector 不建议用于关键生产**，可能变化或被移除。

**Maestro 三种运行模型**：BPMN（可预先建模的结构化流程）/ Flow（开发者顺序流程，2026-08-19 发布）/ Case（长生命周期、异常密集，2026-06 发布；支持 case key、stage、persona、SLA、re-entry、pause、migrate、retry）。支持 instance throttling 与 custom instance ID。

**三次官方事故复盘（这家最有价值的坏消息，来自它自己）**
| 事故 | 根因 | 影响 |
|---|---|---|
| 2026-03-19 Delay 无限循环 | Delayed job 恢复时仍标 `BEGIN` 而非 `RESUME`，从头重跑 | 无限生成 jobs、Redis 拥堵、其他 flow 受影响 |
| 2026-03-20 QueueEvents 过载 | 每个 worker 订阅**所有** job lifecycle 广播，Redis output buffer 爆 | Redis 满、worker crash、**运行日志延迟最高 8 小时** |
| 2026-03-16/17 Worker 架构升级 | PVC 容量未压测 + 无回滚 + dedicated worker 信任配置缺测试 | **多数 Cloud 执行失败或延迟 12–24 小时** |
> 收口句：**Durable Execution 本身不够，还必须有重放语义断言、队列异常检测、基础设施 Canary、可测试回滚。**

**源码级静默失败（GitHub #14328 / #14808）**：Worker 的 `execute-webhook.ts` 先解析 Flow 版本，再在 Sandbox 里执行 Trigger Hook，**只有 trigger output 非空才 submit payload 形成 flow run**。若 Connection refresh 出错或 Webhook 鉴权拒绝发生在**正式 Flow Run 创建之前**，就没有 flow run 可供告警系统捕获，**调用方还可能收到 HTTP 200**。
> → **TriggerAttempt 必须独立记录，不能依赖 FlowRun 存在才有证据。** 这对 Matbox 的 TriggerGateway 是硬需求。

**Waitpoint 竞态处理**：独立 DB row，`flowRunId + stepName` 唯一；类型 DELAY / WEBHOOK / BARRIER；状态 PENDING → COMPLETED；**resume-before-pause 通过预先插入 COMPLETED row 吸收**；重复 callback 靠唯一约束去重；字段含 resumeDateTime、resumePayload、responseToSend。

**Connection 两个成熟设计**：OAuth refresh 用 **Redis 分布式锁**（key = `platformId_externalId`，60 秒）做 single-flight，防并发刷新互相覆盖 token；**删除 Connection 前做二次引用完整性检查**（final integrity gate），防并发编辑/发布产生孤儿 Flow。Connection 字段含 projectIds / externalId / pieceName / type / status / pieceVersion / metadata；`app-connection-service.ts` 先解析 Secret Manager 引用、验证 auth、加密后持久化，执行时再解密并按需刷新。

**FlowRunStatus 十一态**：QUEUED / RUNNING / PAUSED / SUCCEEDED / FAILED / INTERNAL_ERROR / QUOTA_EXCEEDED / TIMEOUT / MEMORY_LIMIT_EXCEEDED / LOG_SIZE_EXCEEDED / CANCELED。
> → 与 UiPath 那份同一方向：**只留 SUCCESS/FAILED 不够**，资源、配额、内部错误、暂停、取消必须有独立语义。

**执行隔离**：生产架构 App → Redis/BullMQ → Worker → Sandbox → Engine；**EE/Cloud 生产明确禁止 UNSANDBOXED 模式**；Network Security 是独立维度，**STRICT 模式可拦 SSRF**，用 allow list 放行内网服务；生产建议每 worker 并发 1 个 flow，0.5 vCPU / 1GB 参考形态。

**Piece Factory 契约**：Piece 是标准 npm/TypeScript package；分层为 PieceDefinition / Auth / Action / Trigger / Props / Output Schema / **AI Metadata** / Version(semver) / Tests / Distribution(official、community 公开 npm、private、archive)。

**Piece 版本固定**：官方 Piece 可从 registry 自动同步（管理页说明约每小时）；**每个 Flow step 固定具体 piece version**；Piece 更新**不会**自动把已发布 Flow 换到新实现，只有 Draft 可显式升级。

**MCP 是工程工具集，不只是 App 动作**：Discovery（`ap_list_flows` / `ap_flow_structure` / `ap_read_step_settings`）→ Piece research（`ap_research_pieces` / `ap_search_actions`）→ Schema（`ap_get_piece_props` / `resolve_property_chain`）→ Validation（`ap_validate_flow` / `ap_validate_step_config`）→ Mutation（`ap_create_flow` / add/update/delete step）→ Run/Test（`ap_test_flow` / `ap_test_step` / `retry_run` / `run_action`）。
> → **"先读真实状态 → 校验 → 受控写入 → 测试"**，这是 Matbox 把自己的平台暴露给 Codex 的现成模板：**不要让 AI 直接改数据库。**

**Project Release / Git**：Release 可从 Git、另一个 Project 或 Rollback 创建；预览含 Flow / Connection / Table changes；**新 Connection 在目标 Project 只是 placeholder，必须重新连接真实 credentials**；**只有 Published flow 能 push 到 Git**。

## 9.2 📄 报告内容（未独立核验）

**⚠️ 口径警告（报告开篇就点破）**：官方 Docs 工程口径是 **over 1,000 connectors**；企业/MCP 营销页用 **12,000+ apps** 覆盖口径。两者不是同一个概念。→ 已并入 §7 的口径归一表。

**Connector 五类**：Pre-built（Workato 维护）/ Universal（HTTP、OpenAPI、GraphQL、SOAP）/ Community（用户贡献）/ Custom SDK（Ruby DSL）/ Custom action（在已有 connector auth 上扩）。

**硬限制矩阵（这份报告最有价值的部分之一）**
| 域 | 公开默认值 |
|---|---|
| SDK connectors | 每 workspace **150**；runtime HTTP **3 min**；compile 5s |
| Recipe | 最多 **1,000 steps**；标准 job timeout **90 分钟**；long pause/action 累计最长 **732 天**；默认并发 **30**（可申请提高） |
| API Platform | 默认 **30 秒**、最大 **240 秒**；payload 5MB；attachment 5GB |
| Embedded API | 总请求 timeout **40s**；多数资源 60–2000 rpm，**按 admin workspace 汇总而非每客户独立** |
| Agent Studio | KB 单文档 **16 MB**；sliding token context **64,000**；Genie conversation API **10 req/s** |
| Polling trigger | 最多连续 **600 次空 poll**；单次最多 1,000 events |
| Job suspension | 最多 **50** |
| OPA | 每 workspace 20 groups；每 group 10 agents；on-prem request **500s** |
| Job/trigger/report 保留 | **30–90 天**（支持 recipe 级 zero-retention） |
| Activity audit log | 默认 **1 年**；外部 streaming 失败**连续 7 天后标记 failed** |

> **同一个外部动作在不同入口有不同 timeout 语义**（Recipe 90min vs API Platform 30s/240s vs SDK 3min vs OPA 500s）。→ 收口时必须做 Canonical Timeout Policy，把 Provider timeout 映射成统一 RunState。

**最狠的一条坏消息**：**API Recipe 请求 timeout 时 Job 可能直接终止，Handle errors 的监控块不会触发。** → **不能把 Provider 内部的「错误处理」当作自己的可靠恢复机制。**

**Embedded（对 Matbox 商业价值最直接的一层）**：managed customer workspace + Embedded API + full-page/widget iframe + 客户级 recipes/jobs/connections/API clients + **自有品牌 Custom OAuth**。
> ⚠️ 但 Embedded API 限额按 **Embed admin workspace 汇总**，不是每客户独立 → **noisy neighbor 是 P0**，Matbox 必须自己做 tenant-aware rate budget 与 backpressure。

**Agent Studio / Genies**：Genie = Job Description + Model + Chat Interface + Knowledge Base + Skills；Recipe 可 `Assign task to genie` 并 pause 等 Agent 返回；Genie 可委派其他 Genie。
> ⚠️ **关键限制**：**verified user access skills 和需要 Business approvals 的 Genie，不能用于完全自治的 Assign task to genie 路径。** → 这证明「用户身份执行」与「后台自治执行」必须是两个 Runtime Profile（USER / AGENT / SERVICE）。与微软 Harness 不可迁移、ServiceNow 的 execution identity 是同一层问题的第三次出现。

**Enterprise MCP**：可把 API collections / recipe functions / API recipes / skills 暴露成远程 MCP tools；客户端含 ChatGPT / Claude / Cursor。**Verified User Access** 按登录终端用户身份执行外部动作；**MCP Apps** 可在 ChatGPT/Claude 内渲染 cards/forms/widgets。

**私网连接（明显强于多数同类）**：OPA（客户网内 outbound TLS WebSocket + mTLS 私有 PKI，**无需开 inbound port**）/ AWS PrivateLink / Azure Private Link / VPW（独立 Workato VPC）。
> ⚠️ **OPA 不是「本地部署 Workato」**：Runtime 仍在 Workato 云，OPA 只是私网访问代理。**必须与 Activepieces 的 self-host 区分。**

**无公开数值 SLA / RPO / RTO**：报告两轮都没在公开 Docs 找到可冻结的统一数值，明确拒绝用「enterprise-grade」自行填 99.9%。→ 保留为 Commercial Gate。

**真实反馈**：G2 **4.7/5、约 750+ reviews**；最常见负面是「好用但贵、规模上来成本明显」。Gartner Peer Insights 的 4.9/5、99% recommend 是 **Workato 自引**（75 eligible reviews），报告明确标注不能替代独立 POC。
