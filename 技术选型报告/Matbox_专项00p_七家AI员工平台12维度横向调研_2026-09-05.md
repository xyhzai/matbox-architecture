## 1｜ServiceNow

**1 建法**：AI Specialist/Worker（岗位）→ AI Agent（专业能力单元）→ Tool/Action/Workflow → Integration Hub Spoke/MCP/API → CMDB/Context Engine（上下文）+ AI Control Tower（治理）。Agent = Role + Instructions + Tools。多 Agent 样板：T2 SOC = Analysis → Containment → Eradication&Recovery → Review&Closure + 按需 Supporting Agents。

**2 连接器**：220+ ServiceNow 自建 Spoke + 40+ 合作伙伴认证；官方 Australia 版兼容性页实际 **302 行**（2026-09-08 点数；Xanadu 版 320 行）；Blueprint 里的 500+ 是"认证连接生态 + MID Server"的更宽口径，**不能与 220+ 混用**。Spoke = 一组类型化 Actions + **凭证别名**（流程只认别名，从不接触真实凭证）+ 示例流程。

**3 真实翻车**：单个 Agent 最多挂 **5-7 个工具**，超了会陷入无限推理循环或任务瘫痪（一线开发者结论）；配置失败**大多不报错**；需 `sn_aia.admin` 角色；Integration Hub 交易额度 Starter 100 万/年、Pro 300 万、企业 600 万，**失败调用也计数**；主要为**单向集成**设计；很多 Spoke 只支持少数动作；JDBC 单步约 5MB 上限。

**4 成本**：⚠️Foundation 约 $70-100/用户，Prime 约 $160-200+/用户（AI 消耗之前）；ITSM Pro 标价 $100-180、规模谈判 $80-150；2500 席以上可降至 $38-90；Agentic 重度使用再加 $50-100+/用户/月。Assist 消耗官方口径：0-4 个工具=25、5-8 个=50、9-20 个=150。**无公开计算器，唯一有约束力的是销售报价**。

**5 可用性**：**不能拿走**。Spoke 跑在 ServiceNow 内，需单独订阅 Integration Hub，原始映射文档原文写明"Matbox 不能把 220+ Spokes 理解成免费拿走直接装进 Matbox"，只能当**能力地图/需求基准**。**但 ServiceNow MCP Server 是真实通道**：外部 Agent 可 headless 调用其表、Skills、平台动作；约束是 subflow 必须在 Flow Designer 显式开启（Manage Security → Callable by Client API + ACL）**且必须同步**（有 wait/异步逻辑的不可用），headless 调用照样烧 Assist。**该通道仅在"客户本来就有 ServiceNow"时有意义。**

**6 中国区**：ServiceNow 自身数据治理**不满足中国数据本地化要求**。可行路径：接第三方（InCountry、STACKIT，声称过 MLPS/CAC）；或自建——数据放境内平台，**敏感数据先脱敏再送全球实例**。

**7 杀掉/改过**：**Otto 正在取代 Now Assist 品牌**（Knowledge 2026）；**2026-04-09 五个老套餐（Standard/Pro/Pro Plus/Enterprise/Enterprise Plus）砍成三个**（Foundation/Advanced/Prime）；**2026-07-09 起第三方模型供应商成为开箱即用 Skills 和 AI Agent 的默认**。

**8 质量数字**：官方 45-60% 转移率可达成；现实很多组织 Virtual Agent 转移率**低于 15%**；**ServiceNow 自己客服转移 75% 的 case，但没有裁减客服人员**（CX Today）。

**9 转人工**：⚠️ServiceNow 专属只查到两条——T2 SOC"带完整 reasoning state 交人"；Blueprint p.17 不可篡改审计轨迹 + 事务性回滚 + inline SLA。其余为行业通用模式，**不算已验证的 ServiceNow 机制**。

**10 出错处置**：⚠️已确认不可篡改审计、事务性回滚、Knowledge 26 官方口径"治理 AI Agent 否则看着它们搞坏东西"。具体谁发现/通知谁/补偿动作/责任归属**未验证**。

**11 配置自动化**：**Spoke Generator**（引导式生成新 Spoke）+ **Build Agent**（自然语言生成生产级应用和 AI Agent，2026 起可在任意 IDE/AI 编程工具内使用）。但仍要装插件、配角色、设 ACL。

## 2｜Salesforce

**1 建法（七家里拆得最细）**：`Agent Type`（权限/渠道大类）→ `Agent Template`（岗位蓝图）→ `Subagent`（**2026 年 4 月由 Topic 更名**）→ `Action`（工具）→ **`Reference Action`（真正执行面：Flow / Apex / API / Prompt Template / MuleSoft API）** → Connector/MCP/External Service。Hybrid Reasoning 的实际含义就在 Reference Action 这层分工：价格/税/库存/审批/写库走 Flow/Apex/API，总结/判断意图走 Prompt Template，一个 Action 可混合两者。

**电商按角色三分**（2026-07 GA）：Shopper Agent（消费者）/ Buyer Agent（B2B 买方）/ Merchant Agent（商家后台）。
拆细方向有数字：IT 域 25+ → 50+ 专业 Agent；HR 域 14 个；行业模板 25+ / 50+ Subagent / 300+ actions。

**2 连接器**：**450+ 是 MuleSoft 整体生态口径，不是 Agentforce 里 450 个一键可挂的 Action**。真正 Flow 内无代码可用的是 `MuleSoft for Flow: Integration`，官方 Q1 2026 口径 **200+**；增长：Winter '26 总数 95 → 2026-01 +91 → 2026-05 +40（推算约 226，**官方未发布 2026-09 精确总数，原报告拒绝编**）。
**"一个 Connector 不是一个能力"**：Shopify Connector 下面仍需拆 Product/Inventory/Order/Customer/Refund 等动作，**给 AI 员工的是动作，不是整个 Connector**。
真实限制：版本管理（minor/patch 自动、major 人工）；外部触发通常靠 polling；**dynamic metadata 场景（NetSuite/Salesforce/Zendesk）不能用于依赖该动态动作的 Agentforce Flow**；很多 Connector 仍 Beta。
**AI 模型本身也被当成 Connector**（OpenAI/Anthropic/Gemini Connector 与 NetSuite、Slack 同层）。

**3 真实翻车**：Demo 好用上生产翻车（在真实数据上报错合同续约日期、报出已下架的支持等级）；⚠️**77% 的 B2B Agentforce 实施因 CRM 数据脏而失败；78% 的团队缺 Apex/MuleSoft/提示工程能力**；**"Agentforce 继承你组织所有的技术债"**——每个 governor limit 问题、权限缺口、自动化冲突它都会找出来。

**4 成本**：官方三种并存——$2/次对话（旧）、**Flex Credits $500/10 万 credits**（每动作 20 credits=$0.10，语音 30 credits=$0.15，费率卡 2026-04-21 更新）、per-user $125/月。2026 年初起 Flex Credits 为新部署推荐模式。**硬依赖 Data Cloud/Data 360，常比 Agentforce 本身还贵**。⚠️算上 Data Cloud（约 18 万美元/年）、Flex Credits、顾问费后实际 $960-1,870/用户/月；首年 24 万 → 三年 94 万美元；实施报价 4-6 周、实际 9-14 个月。

**5 可用性**：MuleSoft 连接器跑在 MuleSoft 运行时，2024-03 起按 Mule Flows/Mule Messages 计费。**OEM/嵌入/转售条款无任何公开文档**，属一事一议定制协议——**只能确认"查不到"，必须走销售+法务**。

**6 中国区**：**Sales Cloud / Service Cloud / Platform 自 2023-12-18 在中国大陆正式可用，跑在阿里云上**，数据本地存储，支持 **MLPS 2.0**；**大中华区所有 Salesforce 产品由阿里云独家销售和运营**；**中国区 AI 能力由阿里云大模型驱动，不是 Salesforce 自己的模型**。

**7 杀掉/改过**：Einstein Copilot → Agentforce（2025-01，**不是纯改名**：前者是检索式问答助手，后者是 topics/actions/instructions 的自主 Agent 框架）；Data Cloud → **Data 360**（2025-10-14）；**Data 360 是第六个名字**（Customer 360 Audiences → Salesforce CDP → Marketing Cloud CDP → Salesforce Genie → Salesforce Data Cloud → Data 360）；Topic → Subagent（2026-04）。

**8 质量数字**：官方自证 Agentforce 在 Salesforce 自家 Help 站点解决 75%+ 访客问题；客户实际**自主解决率 30-40%**（预期 70%）；**KeyBanc 2026-07-09 下调评级，15 万客户里只有约 2.3 万在用**；同期 ARR 12 亿美元、+205%（量的是签约不是效果）。

**9 转人工（七家里最具体之一）**：升级是**显式 Action**，必填输入：意图摘要、触发原因、相关记录 ID，**明确要求上下文字段不能为空**；**Agent 只决定"该转"，Omni-Channel 决定"转给谁"**（技能/队列/在线/承载量）；完整上下文写进 case 记录或聊天窗口。

**10 出错处置**：护栏是可配硬规则（如"不得处理超过 $100 的退款""不得删除记录"）；审计记录谁在什么上下文触发了哪个 Action，Spring '26 起 Flow 执行日志持久化到 Data 360（`ssot__FlowRun__dlm`）可关联 agent 会话；**回滚是弱项且被明确点破：外部 callout 大多没有回滚机制**。

**11 配置自动化**：预制模板（Service Agent / Employee Agent / Campaign Agent / SDR / Sales Coach / Guided Shopping B2B&D2C / B2C / **Setup Agent**），自带预配 topics/actions/guardrails；Spring '26 Agentforce Builder GA（低代码）+ **Agent Script（Beta）**——专门让 Agent 行为可预测的脚本语言。

## 3｜Microsoft

**1 建法**：生成式编排自动组合构建块——actions + topics + knowledge sources + **child agents** + **autonomous triggers**。

**⚠️ 2026-09-05 更正：原文写"topics 在新版界面已被砍掉"过于绝对，是漏了 Harness 这一层。** 准确口径是 Copilot Studio 有**三套 Harness（Agent Runtime），创建时选定、之后双向都不能迁移，只能重建**：
- **GitHub Copilot harness**（2026-08-03 GA）：**没有 Topics**，用大白话 Skills 取代；自主拆步骤、Memory、Skills、安全 Sandbox；**从构建/Preview/Test/Evaluate 阶段就开始计 Copilot Credits**。
- **Standard harness**：**Topics 原封不动还在**（入口收在"Other ways to build"下），Topics/Flows/Connectors/Prompts、经典与生成式编排并存。
- **Copilot Chat harness**：只做 M365 内部知识扩展。

对 Matbox 的直接含义：**Runtime Profile 必须独立于 AI 员工角色**——同一个岗位应能按任务分别走确定性 Workflow、Agentic Planner 或 Computer Use，而不是像微软这样在创建时一次性锁死运行时。
**两样别家没有的**：
- **Entra Agent ID**（2026-05 起 Copilot Studio 给每个新 Agent **自动创建**）：**独立身份类型**（非用户、非传统 service principal），从可复用的 **agent identity blueprint** 继承策略；用 Entitlement Management 的 access packages 管申请/审批/范围/复核/到期；**要求每个 Agent 必须有一个负责的真人做全生命周期监督**。
- **Agent 365**（**2026-05-01 GA，已核实**；Entra Agent ID 本身 **2026-04 GA**）：Agent 注册表/发现层，看全部 Agent 舰队、来源、行为；**跨厂商**（与 Amazon Bedrock、Google Cloud 同步）；start/stop/delete 生命周期治理；Defender/Entra/Intune/Purview 执行策略；专门揪端点上的**影子 Agent**。policy-based runtime controls 到 2026-06 才 public preview。
  **定价形态值得单独记**：Agent 365 是 **$15/user/月**独立版，或含在 M365 E7（$99）里——**治理按人头卖，执行（Copilot Credits）按用量卖，两条计费线并存**。这是 COST-F005 混合订阅+超额模型的现成同类对标。

**2 连接器**：**1,400+** Power Platform 连接器 + Graph 连接器 + Power Query 连接器。连接器本质是 API 的代理/包装层，Copilot Studio / Power Automate / Power Apps / Logic Apps 共用。三档：standard（全套餐）/ premium（部分套餐）/ custom（任意公开 API）。

**3 真实翻车**：**额度烧穿**是最大抱怨（GitHub Copilot 2026-06-01 转按量计费后，"几个月额度一天烧光"，有人第一天就耗掉当月大部分 Pro 额度）；Copilot Studio 出现 Agent 无法编辑、actions 标签页消失；G2 评价"感觉受限、跟宣传不一样、比较基础"；**Teams 里转人工会卡死无响应**（常见原因是 Conditional Access 挡住令牌获取）；多数企业距规模化部署还有 12-18 个月。

**4 成本**：$200/月一个容量包（25,000 Copilot Credits）；按量付费约 $0.01/credit；**按 credit 计费、租户层面共享池、不按席位**——成本取决于 Agent 消耗而非用户数；2025-09 从"按消息"改为"按 credit"。⚠️第三方估算：跑 5 个 Agent 约 $3,000-6,000/月。

**5 可用性**：连接器是微软平台内代理层，拿不出来；premium/custom 需独立 Power Apps/Power Automate 授权。**但有 ISV 通道**：`Power Automate Embed Pay-as-you-go for ISVs`（预览），per-app/per-flow 独立套餐允许不限人数使用。**代价是把 Matbox 建在 Power Platform 上。**

**6 中国区**：**Microsoft 365 Copilot 不在 21Vianet 中国云提供；Azure Copilot 也不在国家云可用**（Copilot 服务说明的可用性表只列 Worldwide 与 US Government 两朵云；全部 AI Copilot API 在 21Vianet 下不可用）。Azure 中国是物理隔离实例，由世纪互联/上海蓝云运营。
**⚠️ 比"不支持"更重的一层（2026-09-05 补）**：21Vianet 版 Microsoft 365 **2026-06-01 起停止新购、2027-01 起停止续订**，存量合同到期为止。也就是说微软不是"暂时没上 Copilot"，而是在收摊整个中国 M365 通道。**七家里最硬的否，且还在恶化。**

**7 杀掉什么**：Power Virtual Agents 2023-11 并入 Copilot Studio，**已不作为独立产品存在**（老 PVA 机器人被自动搬入）；新版**砍掉 topics**，替代品被指并不等价——对存量客户的真实破坏性变更。

**8 质量数字**：2026 Q1 已部署 12 万+自定义 Agent；M365 生态活跃 Agent 同比 15 倍（大企业 18 倍）。宣称每人每天省 14-26 分钟。**但真实口径**：对 5 万 Word 用户的分析显示**每个被采纳的输出省 7 分钟；若采纳率仅 20-30%，每次提示净节省只有 1.4-2.1 分钟**——"这是每次成功交互的价值，不是每次尝试的价值"。

**9 转人工**：内置 **`Escalate` 系统 topic**；编辑画布上的 **Transfer Conversation 节点**，可附**只给人工看的私密留言**（存 `va_AgentMessage` 上下文变量）；对接 Dynamics 365 Omnichannel。**别家没有的模式**：用 M365 Agents SDK 的 skills，可"转给人工但 Copilot Studio 仍掌控通信通道"。

**10 出错处置**：⚠️只有设计层指引（每个集成点要有错误处理、用户可读的失败信息、超 10 秒走异步）；治理与停机能力在 Agent 365（start/stop/delete）和 Purview/Defender。**未找到事务回滚机制，标为未验证。**

**11 配置自动化**：生成式编排自动组合构建块；模板；Entra 自动为每个 Agent 建身份。用户反馈"高级定制仍需额外技术知识"。

## 4｜UiPath

**1 建法**：Agent = **系统提示词**（role/goal/constraints + 何时调工具/升级）+ **Tools**（RPA 流程、Integration Service 连接器、**其他 Agent 当工具**）+ **Context Grounding**（带权限的知识库索引）+ **Escalations** + **Guardrails**（PII 遮蔽/有害内容过滤/自定义规则）+ 输入输出参数 schema。上层 **Maestro**：BPMN 定顺序 + DMN 定决策。

**⚠️ DMN 的成熟度必须标出来（2026-09-05 补，直接影响 ACTION-F006）**：Maestro 的 Business Rules 官方页面标题即写 **"(preview)"**，支持 **DMN v1.3**、带版本管理。**Matbox 的 ACTION-F006 Workflow Registry 是按 BPMN + DMN 设计的，来源就是这里——但抄的是一个仍在 preview 的能力。** ACTION-F006 正文是否要跟着加限定，留到七家收口时一并处理，本文只作标注。

**数量（原写"查不到"，2026-09-05 已补上）**：Marketplace 的 Integration Service 页面**约 164 个结果**，另一个官方 Connector 合集页 **136 listings**，两者 provider/filter 范围不同、不可相加。冻结口径为"**约百余个**"。1,300+ 是 2021 年旧数据、口径不同，不可用。

**3 真实翻车（整个研究里最硬的一组）**：

**6 中国区**：数据驻留文档中**无中国区**（最近新增韩国区 GA），官方让"联系客户团队"。**支持自托管 + 气隙（air-gapped）部署，技术上可装在自有基础设施** ✅ 已核实——与 Microsoft 的"直接不可用"性质不同。

**⚠️ 但这条要打两处折（2026-09-05 补）**：

## 5｜Zapier

**1 建法（门槛最低，也最浅）**：Agent = 大白话目标 + 自定义 instructions（语气、范围、**升级触发条件**、行为准则）+ 可访问的 triggers/actions + 实时数据源（Google Drive/Box/Notion/Asana）+ 网页搜索。**Agent 可以叫其他 Agent**。80+ 免费预制 Agent 可用大白话改。
局限：定制深度不如 CrewAI/AutoGen；记忆能力"仍在成熟中"。
⚠️**「Agents 绑死 OpenAI，不能换 Anthropic/Gemini/本地模型」——2026-09-05 复查未能证实，本条撤回为待验证**：唯一来源是竞品博客（inkeep），不可采信。Zapier 官方 blog 明确 **AI by Zapier 步骤**可在 OpenAI / Anthropic / Google / Azure OpenAI / Amazon Bedrock 之间下拉切换，但那是**另一个产品面**；关于 **Agents 本身**用哪个模型、能否更换，官方文档中未检出任何陈述。**不得作为架构依据**，须用真账号验证。

**2 连接器（规模碾压）**：规模数字必须分两档看（2026-09-05 逐条实地复查后重写）。

- **官方原文（已逐字命中 `zapier.com/press`）**：`over 3.4 million businesses`、`over 9,000 apps`、`800+ people across 40 countries`。About 页另给累计 **81 billion tasks**、累计 **25 million Zaps**、**69% Fortune 1000**。

- **基本没融资、自己盈利**：属实，早期仅融约 120–130 万美元。
- 计费单位 **task = 一次成功的动作步骤**（触发器和过滤器免费）。

- **Zapier Embedded / Partner Embeds**：合作伙伴可把 Zapier 应用库**直接嵌进自己产品**，可只放预制 Zap 模板，也可嵌完整 Zap 编辑器
- **Workflow API 对合作伙伴免费**；合作伙伴计划免费
- ⚠️代价：**终端用户仍需自己的 Zapier 订阅**（$19.99/月起），并引入对 Zapier 的依赖

**7 杀掉什么**：**Zapier Functions 2026-09-01 退役**（2026-06-01 起不能新建，存量须迁至 Code by Zapier）；**ChatGPT/OpenAI 的 Assistants API 相关步骤弃用，必须在 2026-08-26 前迁移否则 Zap 停止工作**（因 OpenAI 自己弃用 Assistants API）。
→ **"被上游逼停"第二次出现。**

**8 质量数字**：未找到解决率类独立指标。可用硬数字为规模本身与那处评分分裂。

**9 转人工**：**最弱的一家**——只有 instructions 里定义"升级触发条件"，无 reasoning state 移交、无 Continue/End 粒度。

**10 出错处置（反而七家最具体）**：
- **Autoreplay**：某步失败自动重试**最多 5 次**，最后一次约在首次报错后 **10 小时 35 分**
- **重放只重跑失败步骤，不重跑已成功步骤**（幂等思路）
- **Zap 反复报错会自动关停**
- 付费版可在 Zap History 手动重放，支持批量
- ⚠️**大坑：Autoreplay 期间 Zapier 不发任何报错邮件**，只有最后一次也失败才发一封——前面 10 小时用户毫不知情

**11 配置自动化**：全程大白话，80+ 预制 Agent 直接改。官方定位原话"**IT 设护栏，任何人不用等审批就能建**"——与 Workato 是两个极端。

## 6｜Intercom / Fin

**与前五家根本不是一个物种：它不是搭建平台，是造好的成品 Agent，你只做配置。**

**1 建法**：**知识源**（5 类：帮助中心文章、内部文章、片段、PDF/文档、同步的公开 URL；最多 100 个外部源；统一在 Knowledge Hub；导入耗时 10 分钟至 10 小时）+ **Procedures**（大白话流程指令，Fin 照走并实时适应）+ 上线前定死的护栏/接地/升级规则（只从批准内容回答；退款、承诺、边界情况一律转人工）。

**2 连接器策略（整个研究里最重要的反例）**：**Fin 没有自建连接器生态，是"蹭"来的**——原生 **MCP 连接器**（官方文档 "Add MCP connectors for popular apps or custom MCPs"）+ API Data Connectors（自定义动作，JSON/XML）+ **通过 Zapier 接入"数千个应用"**；直连的只有 Linear、Stripe、Shopify、Salesforce、HubSpot、Statuspage 等少数。
→ **七家里增长最快的 AI Agent 公司，选择了"获得连接器访问权"而不是"拥有连接器生态"。**

**3 真实翻车**：Reddit 帖《为什么我的 Intercom 账单从 4 千跳到 9 千美元/月》，用户原话定价"比营销页面说的复杂得多"（$0.99 结果计费之外还有外呼/WhatsApp/SMS/电话等叠加与持续维护）；G2/Capterra/TrustRadius 一致模式——**客户问计费或技术问题时官方支持响应慢、不解决**；AI 在复杂或非常具体的问题上理解不了；报表深度不够。同时 G2 **4.5/5，3,811 条评价**。

**4 成本（七家唯一真正的按结果计费）**：$0.99 一个"结果"，四种：解决 $0.99、**转人工交接 $0.99**、判定不合格 $0.99、**判定为合格线索 $9.99**；基础套餐 $49/月含 50 次解决。
对照：ServiceNow 在自家 Blueprint 里**明确否认**自己是按结果计费（"outcome 是扩张的理由，不一定是计费单位"）。

**5 可用性（不建议，窗口正在关闭）**：有 "Fin for platforms" 产品线，但 Fin 是成品客服 Agent，嵌它等于嵌别家完整产品体验。**更关键：Salesforce 已于 2026-06-15 签署协议以约 36 亿美元收购 Fin**，预计 Salesforce FY2027 Q4 完成（**尚未交割**），将为 Salesforce 带来约 3 万 AI 客户——任何对 Fin 的依赖最终会变成对 Salesforce 的依赖。

**6 中国区**：数据层——默认美国；区域托管只有 **美国 / 欧盟（AWS 都柏林 eu-west-1）/ 澳大利亚（AWS 悉尼 ap-southeast-2）**，**无中国**；实操坑：**已有 workspace 无法跨区迁移**，只能新建 workspace 手工搬数据和配置。

**7 杀掉什么**：**Tasks → Procedures，2026-03-12 起禁止新建 Task**（存量继续支持，仅可编辑/暂停/管理）；公司实体 2026-05 由 Intercom 改名为 Fin。

**8 质量数字（七家最完整，也是官方与独立落差最大的）**：
- 官方：7,000+ 客户、4,000 万+对话，平均解决率 **67%**，提供 **65% 的 100 万美元履约保证**
- Fin 2 开箱声称 51%
- 真实客户区间 42-50%
- **独立测试（500 张工单）：38%**
- 官方自述轨迹：经 20 多次功能升级从 41% 爬到 51%

**9 转人工**：规则上线前定死。**别家没有的设计："转人工交接"本身是可计费的结果（$0.99）**——转给人工在商业模型上算一次成功产出，不是失败。

**10 上线前测试（七家最强）**：
- **Simulations**：后台跑 Procedure，**不产生任何面向客户的输出**，官方称"上线前验证逻辑最安全的方式"
- **批量测试**：拿真实客户问题批量模拟，覆盖多品牌/多用户/多语言
- **Risk paths**：专测最易在生产出问题的路径——外部数据缺失、条件不满足、必须走兜底分支
- **Edge cases**：边界输入，尤其针对时间敏感逻辑、数值阈值、自由文本
- **按受众预览**：先建"内部测试者"受众验证再放给客户
- 失败模拟可整段回看

**11 配置自动化**：七家里"不用建"程度最高——因为没得建。代价是**只能做客服**。

## 7｜Workato

**1 建法**：Agent 叫 **genie**。Genie = 一组 **Skills**，每个 Skill 有**两部分**：**执行逻辑** + **skill prompt**（配在 genie 上，告诉它何时、如何使用该 skill）。Skill 可连：任意 Workato 支持的应用、自定义 API、数据表、**或外部 MCP server**。

**2 连接器**：**1,200+ 深度连接器**。**MCP 双向，七家最完整**：genie 既是 **MCP 客户端**（无需自定义 skill 即可连任意第三方 MCP server），自身**也能被暴露为 MCP server**，被 Claude、ChatGPT、Cursor 调用。

**3 真实翻车（公司层面而非产品层面）**：**估值从 57 亿美元（2021 年底 E 轮）跌至约 17 亿美元**（2025-06 二级市场）；裁员 2023-02 裁 85 人（10%），后续再裁数百人（招聘/销售/市场受冲击最大）；Glassdoor 原话"裁员后一片混乱，很多项目停滞"，预算与方向无可见性；⚠️定位抱怨——中型 GTM 团队付 **$25K-500K/年**买到的基础设施 **"90% 超出其使用场景"**。**但产品口碑七家最高：G2 4.7/5，751+ 评价，81% 五星。**

**4 成本**：按 task 计费（1 task = recipe 里一个动作）；工作区内**连接数/recipe 数/开发者数/管理员数不限**；task 包起步 100 万。⚠️第三方区间：入门约 1 万美元/年，中型 2.5-5 万，200+ recipe 企业级 7.5-15 万。不公开定价。

**5 可用性（三样对 Matbox 直接有参考价值）**：
- **XChange**：把 genie 打包，走**受治理的审核批准流程**分发到子工作区或发布到社区库
- **BYOLLM**：企业可带自己已批准的模型，官方明说为"有严格数据驻留或模型治理要求"的组织准备
- **On-prem agent (OPA)**：装在企业内网的轻量代理，**从防火墙内部向外建立安全隧道，无需开任何入站端口**

**6 中国区（七家唯一有真正中国数据中心的）**：**所有客户数据（recipe、连接、共享资产、作业日志）全部在中国境内处理存储**，完全隔离的区域部署，带 RBAC、SAML SSO、SCIM、企业密钥管理、数据脱敏、可配置保留期。区域数据中心共八个：美国、欧盟、日本、新加坡、**中国**、以色列、澳大利亚、韩国。
**但限制正是给 Matbox 的教训**：**MCP server 在中国数据中心不可用**；API 平台自定义域名在中国数据中心不支持；**部分功能依赖的 AI 模型基础设施不在中国区运行**。
→ 与 Salesforce（中国区换阿里云模型）共同证明：**跨区部署必然带来能力差异，必须提前设计并明确告知客户。**

**7 杀掉什么**：**on-prem agent 2.19.0 以下版本 2026-01-08 彻底停用**——官方原话：到停用日 **agent 不再连接 Workato，所有正在运行的 recipe 中断**（硬切断）；**Pipedrive 连接器 v1 触发器/动作弃用（因 Pipedrive 自己 sunset 了 API）**；QuickBooks 轮询触发器弃用（迁 webhook）；旧 Kafka 触发器弃用。
→ **"被上游逼停"第三次出现。**

**8 质量数字**：未找到解决率类独立指标。最强信号为 G2 4.7/5、81% 五星——**产品满意度七家最高，但公司本身在收缩**，此反差本身值得记录。

**9 转人工/审批**：genie 在执行**特权动作前先取得用户同意**，并**按企业已有业务流程向管理者收集审批**。机制细节不如 UiPath 的 Continue/End，但"接进公司现有审批流程"而非自建一套的思路值得注意。

**10 出错处置（工作流层面七家最成熟）**：
- **错误监控步骤**：检查动作是否完成，出错可重试或跳到下一步
- **`Handle errors` 控制语句**：监控**一组**步骤，块内任一步失败即可重试 / 记录 / 告警 / 执行补救步骤
- 可配置重试次数与间隔；401 + WWW-Authenticate 内置重试
- **RecipeOps 连接器：用 recipe 监控和管理其他 recipe**——`Job failed` 触发器可取 Recipe ID、Job ID、错误类型、错误信息；停掉的 recipe 与失败作业可自动响应与通知
→ **用自动化监控自动化**，Matbox 无对应设计。

**11 配置自动化（治理最紧，与 Zapier 两个极端）**：有 AI 辅助建 recipe、低代码 Agent Studio，但**开发者只能在 IT 预先批准的 MCP skills 范围内工作，超范围需提工单**。

## 8｜已经浮现但尚未结论的横向观察

以下不是总结，只是记录调研过程中反复出现、待与用户侧报告合并后再判断的现象：

1. **"被上游逼停"出现三次**（UiPath 被 Snowflake/Salesforce 逼、Zapier 被 OpenAI 逼、Workato 被 Pipedrive 逼）——连接器目录会按**别人的时间表**报废，不是自己能控的。
2. **跨区能力差异出现两次**（Salesforce 中国区换阿里云模型；Workato 中国 DC 无 MCP server、部分 AI 功能不可用）。
3. **"官方数字 vs 独立数字"落差最大的是 Fin**（67% vs 38%）；**最诚实的自曝是 ServiceNow**（自家客服转移 75% 但没裁人）和 **Microsoft**（每次成功交互 7 分钟 vs 每次尝试 1.4-2.1 分钟）。
4. **治理松紧是一条明确的光谱**：Zapier（IT 设护栏，人人可建）↔ Workato（IT 先批准才能用）。
5. **Fin 证明了"不自建连接器生态"也能跑通**（MCP + 蹭 Zapier），这对"先建连接生态"这条判断是修正而非推翻——需要的是**访问权**，不必然是**所有权**。
