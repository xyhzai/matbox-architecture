### 4.1 测试方法名必须带 TestID —— 这是硬要求

上表每一条 TestID，都要有**至少一个测试方法**，方法名以该编号开头：

```java
@Test

void dqT012_describeWhatThisCriterionVerifies() {   // ← 后半段换成「这条在验什么」，英文小驼峰
    // Given / When / Then 三段照上表那一条写，不要自己发挥
}
```

**为什么是方法名，不是只打 `@Tag`**：`@Tag` 不会写进 Maven Surefire 的 XML 报告（Surefire 至今不导出 JUnit 5 的 tag），CI 那边读不到，等于没标。而 `<testcase name="...">` 里一定有方法名——**方法名是唯一不依赖任何插件、任何配置就能从 CI 读回来的载体**。`@Tag` 仍然建议加，但它只用来筛选要跑哪些，不承担追溯。

规则就三条：

1. 方法名 **必须**以 `dqTxxx_` 开头，`xxx` 是三位数字，与上表编号一一对应
2. 一条 TestID 可以有多个测试方法（`dqT012_a`、`dqT012_b`…），但**不能一条都没有**
3. 不要给上表以外的编号写测试 —— 那条不归你，写了会在反向核查里被判成孤儿测试

**不新建平行鉴权体系**——完全复用 F-TENANT-001（TENANT-F001~F006）与 F-CRED-001（CRED-F001~F009）已冻结的模式：

- **架构原则第59条**：AI 该不该停下来问人，按**动作后果**四级分类，不按 AI 自报的把握度。只读/查资料不问；改草稿留痕；碰外部系统排队；上线/删数据/改权限必须问人。
- **架构原则第74条**：要检验一个测试是不是真的，就把被测代码拿掉看它还通不通过。换坏了还能 PASS 的测试不算测试。
- **架构原则第76条**：引用别的模块的枚举/字段时，**不要抄一份下来写「固定为」**，要写明「以某文档某节为唯一来源」。抄下来那一刻它就开始过期，而且过期没有任何提示。

## 7 · 完工时必须交出什么

- QualityRun + 各 ScannerRun 记录
- Evidence 包：NormalizedFinding / GateDecision，绑定 EvidenceBundleID，**不可变**
- 返修记录（如涉及）：RepairAttempt，绑父 QualityRun + 第几次尝试
- 最终验收结论：AcceptanceRunID（`MANUAL_ACCEPTANCE`），由**独立** Acceptance Owner 出具——修复者不能自我批准

## 8 · 怎么起本地环境

**先装这两样**（缺一样第 ④ 步跑不了）：

| 装什么 | 版本 | 验证 |
|---|---|---|
| JDK | **17**（Temurin/Zulu 均可） | `java -version` 显示 17.x |
| Maven | 3.9+ | `mvn -v` 显示 3.9 以上且指向 JDK 17 |

**再起一个 PostgreSQL 16**（本地装或容器都行）：

```bash
docker run -d --name matbox-pg -p 5432:5432 \
  -e POSTGRES_USER=matbox -e POSTGRES_PASSWORD=matbox \
  -e POSTGRES_DB=matbox postgres:16
```

**装不了本地环境也能干活**：只推分支、让 CI 跑。`.github/workflows/backend-build.yml` 会起真 postgres:16、跑 Flyway 迁移、跑全部测试。**判定以 CI 为准，本地只是快一点。**

**当前事实**（不是规格）：骨架已经建好，CI 在默认分支上是绿的；`backend/modules/dev-quality/` 里已有 pom、应用入口、8 个契约类、V1 迁移与两个测试。你不是从零开始。
